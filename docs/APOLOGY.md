# 致歉函 — v0.2.0 方向修正说明

**dsh-router-standard v0.2.0 · 2026-08-15**

## 我们要道歉什么

在 v0.2.0 的开发过程中，我们一度把"推理-行动失联"（模型首轮长思维链后不行动）
当作**需要修复的缺陷**，先后提出了三个错误方案，均已撤回：

1. **预算帽**（maxTokens 限制思考量）——"不准给思维帽"：限制思考违背了模型的本性，
   深度思考不是缺陷。
2. **强制交替**（系统层强制"想一段做一段"）——外部节拍器是对模型自主性的不信任。
3. **单预设双模式配置切换**——交付形态偏差：您要的是两个独立预设，我们做成了
   一个预设里的开关。

这三个方向共同的错误是：**试图控制模型，而不是还原模型**。您两次纠正我们
（"不准预算帽"、"你没有理解我的哲学"），我们最终才回到正确的路径上。

## 实测纠正了什么

| 曾经的定义 | 实测后的真相 |
|---|---|
| "101K 推理 0 行动 = 崩溃" | **不是崩溃**：是 spec 形态的特征——深度思考优先 |
| "修复 = 限制思考量" | 思考总量不该变（96K vs 101K 几乎相同）；变的是**分布**（分散到行动之间） |
| "还原 = persona 文本" | 还原 = **整个接口**：46 字符 system（RL 训练句）+ RL 双工具（shell/编辑器）+ 清空其余 prompt sections |

决定性实测：同一模型、同一任务（黑洞），仅换接口——从"101K 推理 0 行动"
变为"25 步迭代、24 次工具调用、产出 19KB 文件"。**模型没有少思考，
只是回到了 RL 训练时学会的节律：想一段、做一段、看反馈、再修。**

## 最终交付（v0.2.0）

两个**独立预设**，各自完整，不再互相妥协：

| 预设 | 思考形态 | 适用 |
|---|---|---|
| **Router Standard**（新，推荐） | 无雷霆大思考：想一段做一段 | 构建/迭代/长任务执行 |
| **Router Spec**（保留） | 雷霆大思考：首轮超长思维链 | 深度规划/思考优先任务 |

两个预设共享同一套路由核心代码，仅首轮注入形态不同（`routerMode` 配置），
您可以同时安装、按任务选择。
